# 执行、后期与验收

## 预检

锁定 1–3 个方案、预算及目标；默认每个模型 job 最多一次有证据的上传重试，质量修订每方案最多一次，仍须在用户允许的预算内。计划说明这些重试可能增加费用；不因缺具体预算反复询问正常已授权生成，但超出明确预算必须停。

核对实际模式参数、素材数量/大小、单条/总时长、FPS/尺寸、图像清晰度/角色/顺序。剔除无用概念海报，商品多角度优先。改尺寸、静音、裁切均保留原件并记录命令。任务并发默认 1；已知允许时最多 3，依赖任务严格排序。最多三种成片不等于可无限并发其片段。

## 防重复与失败分类

| 状态 | 处理 |
|---|---|
| 已有 ID，排队/慢/查询断网 | 用原 ID 查询，保留错误；不能重生成 |
| 返回结束但 error 非空 | 失败；保留原响应，区分任务失败与下载失败 |
| 上传明确失败且服务确认未建任务 | 等待退避，原输入最多重试一次，记录新 attempt |
| HTTP 超时、进程崩溃、没有 ID 但不知是否已提交 | submission_unknown；先核查，绝不以无 ID 推断未生成 |
| 参数/认证错误 | 修复实际原因，不重复相同请求，不静默换模型/降清晰度 |
| 配额/并发限制 | 等待已有任务或需用户处理额度；不要制造更多并行请求 |
| 下载失败/URL 过期 | 重新 query/下载原任务；不 submit |

脚本提交前原子建立 state.json；重复目录拒绝提交。崩溃后若 state 停在 submitting，检查已存 submit stdout 或服务端，确认 ID 后可人工补全状态；禁止删除 state 来“重试”。明确未创建任务的重试在新 attempt 目录下做，原失败日志保留并关联。工具调用日志可能含临时签名 URL，归档前脱敏，凭据不记录。

## 后期政策

- 原模型视频保留、哈希。严格 CFR 全长按预定每段帧数归一 FPS/尺寸、裁切后拼接；不足帧不能偷偷循环/冻结/变速补齐，回到策略判断。VFR 用 PTS 或先记录规范化。
- 切点查前后数秒，人物/场景/颜色/动作要连贯。后期能修帧数就不重跑模型。淡化或节奏改写是创作变化，应记新版本/配置。
- `preserve_source` 仅当原台词适配商品且用户目标允许。源商品卖点不适配时用新音轨，或经明确说明仅作视觉评测；成片不能被标为可直接投放。剧情改写通常 generated/rewrite；无声仅在目标允许时。
- 严格音轨复制可用原 AAC stream copy，验音频包哈希；不能用容器文件整体哈希证明音轨没变。音频略长于视频合理记录，不强行删掉尾音。需要重编码时记录不能字节等同。
- 字幕三选一：源字幕、模型字幕、后期重建。模型已烧字先检查，不能再直接覆盖 OCR 造成叠字。FFmpeg 缺字幕滤镜用可用渲染器或保留无字幕版本并说明，不隐瞒。

辅助组装脚本适用于相同尺寸的 CFR 片段，按 parts.json 中 frames 裁切，支持 source/segments/none 音频模式；限制见命令 help。复杂音频编辑/字幕/PTS 剪辑由等价媒体工具处理并归档 argv。

## 验收层级

1. **技术最低线**：路径属于本任务、非零大小、SHA256、probe、全片 decode；时长/目标帧数、尺寸/比例、音轨符合政策。无效文件不发布为 ready。
2. **商品硬门槛**：检查所有主要展示段的 SKU、颜色、结构、包装/文字、手物关系。镜头再像，细肩带变宽肩带也是不通过。
3. **参考/故事**：R1 检节奏与关键动作；R2/R3 检因果/模块完整；R5 检同类情绪与商品回报。前贴好看但没桥接到产品要修订。
4. **连续性**：全片代表帧＋接缝加密；人物、衣服颜色、光线、空间不突变；首尾帧模式查实际端点，不假设循环成立。
5. **声音/字幕**：音轨存在、能解码、音量/静音只是技术检查；ASR 检关键台词覆盖，回听疑点，必要时口型核对。未人工听审或逐帧检查需明确，不能写成已完成。

技术验收通过可交付实验预览，但语义不达标须标 needs_revision，不声称 1:1 或已满足投放。助手观察不写用户评分。记录 qa.{technical,product,reference,narrative,continuity,audio,limitations,verdict} 及抽样范围/证据路径。

## 交付

生成 results.md，对每个方法/版本给视频链接、核心差异、实际模型/时长、质量限制、元数据入口。平台有要求则验证正确商品＋参考、并列多个版本、元数据读回、媒体 Range/播放、评价刷新留存。保留未完成任务与恢复命令，不把提交链接当最终成片。
